# 概念

Forgeyard 的各個部分怎麼搭在一起，依照你會碰到的順序說明。每一節都會講這是什麼、它幫你做什麼，以及要注意的地方。

## 機器與 agent

**機器**是 Forgeyard 可以在上面執行工作的任何電腦：GPU 伺服器、工作站，或只有 CPU 的電腦。每台機器都執行一個 **agent**（代理程式），這是一支小程式，它會：

- 回報機器的硬體：每張 GPU（型號、記憶體、驅動程式、負載、溫度）、CPU 和 RAM；
- 和伺服器保持一條連線，而這條連線是**由 agent 發起**的：伺服器永遠不需要主動連到機器，所以就算機器在防火牆或 NAT 後面，只要它連得到伺服器就能運作；
- 啟動、監看並停止伺服器要求它在這台機器上執行的東西。

機器只需要**加入**一次，使用從 **Machines** → **Add a machine** 取得的**加入權杖**（join token）：它只能用一次、15 分鐘內有效，伺服器只保留它的雜湊值。agent 會用它換到這台機器自己的**憑據**，存放在 agent 的狀態目錄（`/var/lib/forgeyard-agent`，權限 0600）。之後啟動就不再需要權杖。

agent 只透過伺服器的**憑證授權單位**（CA）來信任伺服器，並以加入指令裡的指紋釘選這個 CA：中間如果有別的機器拿著其他憑證，會被拒絕。請看[信任 CA](quick-start.md#2-create-the-owner-and-trust-the-ca)。

agent 連線中時，機器顯示 **online**；超過 30 秒沒有收到任何訊息時，顯示 **offline**（agent 每 10 秒送一次心跳）。agent 會自己重新連線。管理員可以**撤銷**一台機器（它的憑據立刻失效），或把它**移除**。

停止或重新啟動 agent **不會停掉它的工作負載**：重新啟動的 agent 會找到它們並接手管理。這就是安裝的服務使用 `KillMode=process` 的原因。

agent 從 `/etc/forgeyard/agent.toml`、`FORGEYARD_*` 環境變數和命令列旗標讀取設定（[完整列表](reference.md#agent-settings)）。

## GPU 存取權

預設情況下，Forgeyard 可以使用機器上的每一張 GPU。如果機器要和其他人或其他程式共用，管理員可以在 **Machines** → **Change GPU access** 選擇 Forgeyard 可以用哪些卡。不在清單上的卡，絕不會分配給 Forgeyard 執行的任何東西。

- 分配給獨占副本的 GPU 只屬於那個副本。
- 共用一張卡的副本（嵌入模型、重排序模型、語音轉文字預設都是）只能使用自己保留的記憶體量，所以一張卡可以放好幾個。
- 記憶體以卡片當下回報的**可用**量為準，所以別人正在用的記憶體會被扣除，另外再保留一段安全餘裕（512 MiB）。
- 行程只會在 `CUDA_VISIBLE_DEVICES`（NVIDIA）或 `ROCR_VISIBLE_DEVICES`（AMD）裡拿到自己那幾張卡的 ID；容器也只會被傳入自己的卡。正在使用中的卡不能從清單中移除。

## 工作負載

**工作負載**是要在你的機器上執行的東西：

- **服務**會一直執行到你停止它為止。它會被做健康檢查，結束時會被重新啟動；
- **任務**會執行到結束，可以設定重試次數和時間上限。

每個工作負載有 1 到 16 個**副本**，每個副本在一台機器上。工作負載可以用**容器**（機器上的 Docker 或 Podman）或**行程**（由 agent 啟動的程式）的方式執行。

隔離方式簡述如下：

- 行程以無特權帳號（`forgeyard-run`）執行，絕不以 root 執行，而且環境變數是空的：只有工作負載宣告的變數，加上它的 GPU 和連接埠變數。
- 容器以容器引擎的預設值加上 `no-new-privileges` 執行，絕不使用 `--privileged`。
- 資源限制：容器使用 `--cpus` 和 `--memory`；行程在有 systemd 的主機上使用 systemd scope，否則使用 rlimit。

只有管理員和 operator 可以建立工作負載，因為能建立工作負載的人，就能在機器上執行程式碼。模型部署也是一種工作負載；大部分的人只需要部署模型。

## 模型、recipe 與估算

- **目錄**列出你可以部署的模型。管理員可以從**推薦**清單、**Hugging Face 搜尋**，或從某個來源加入模型：`hf://org/name`、一個 GGUF 網址，或用 `local://` 指向機器上的某個目錄。加入模型時只會讀取它的資訊，不會下載。
- **recipe**（配方）描述某一類模型要怎麼執行：用哪個引擎、哪個容器映像檔（以 digest 釘選）或發行版本、哪些參數，以及需要多少記憶體。內建的有：`vllm`（NVIDIA 和 AMD 上的對話模型）、`vllm-pooling`（嵌入與重排序）、`llama-cpp`（NVIDIA、AMD（ROCm 或 Vulkan）或 CPU 上的 GGUF）和 `faster-whisper`（語音轉文字）。
- **估算**是一份副本需要的記憶體：權重、依你選的上下文長度和並行數計算的 KV cache、引擎本身的額外開銷、CUDA context，以及能讀圖片的模型的視覺編碼器。部署頁面會在下載任何東西之前，逐項顯示估算結果和放得下的位置。
- 每台機器上的**模型快取**（預設 `/srv/forgeyard-models`）保存下載下來的檔案，檔案會以 checksum 檢查，並由這台機器上的所有副本共用。容器會以唯讀方式掛載自己的模型。

## 部署與閘道

**部署**用一個 recipe 執行一個模型，包含一個或多個副本。Forgeyard 會：

1. 把每個副本放到放得下的地方：選擇夠大的卡中最剛好的那張（讓整張空著的卡留給大模型），盡可能放在已經快取了這個模型的機器上，並盡可能把同一個部署的副本放在**不同機器**上；
2. 如果哪裡都放不下，就拒絕這個部署，並逐台機器說明原因和差多少；
3. 在那台機器上下載模型、啟動引擎，並等到它變成健康狀態。

每個就緒的部署都以它的模型名稱，在 **`https://<server>:7860/v1`**（也就是**閘道**）以 OpenAI API 提供服務：`/v1/models`、`/v1/chat/completions`、`/v1/completions`、`/v1/embeddings`、`/v1/rerank`、`/v1/score`、`/v1/audio/transcriptions` 和 `/translations`。`/v1/models` 列出你的金鑰可以用的模型；部署停止後，它會從清單消失，直到再次啟動為止，除非它的路由能把請求送到你的金鑰可以用的雲端供應商。

閘道會把每個請求送到正在處理中請求數最少的就緒副本；如果某個副本沒有回應，就改送下一個。副本無法繞過閘道直接使用：每個副本都有一把只有閘道知道的內部金鑰，agent 會拒絕送到副本連接埠的其他所有請求。

**Playground** 讓你以自己的身分、不需要 API 金鑰，透過同一個閘道試用模型：對話（串流，能讀圖片的模型也可以附上圖片）、嵌入、重排序和語音轉文字。它的請求在 Usage 裡算作 `console`；它的雲端設定對管理員是 **Allowed**，對其他人則是他們能替自己金鑰設定的最大值。

## 對話中的圖片、音訊與影片

能讀圖片的模型（Qwen3-VL、Gemma 3 與 4 等）在 `/v1/chat/completions` 以 OpenAI 的內容區塊（content parts）接收圖片。模型能接受什麼，是在加入目錄時讀出來的：從它的 `config.json`，或 GGUF 模型的 **projector 檔**（`mmproj-*.gguf`，llama.cpp 要靠它才看得到圖片）。目錄會把它和授權一起列出。

- 圖片可以用 `data:` URI 送，也可以用 `https://` 網址：**閘道會自己下載**，再把資料轉給引擎。引擎從不自己下載任何東西，而且閘道只連公開位址，所以請求沒辦法讓你的伺服器去存取你自己的內部網路。
- 每個部署一次請求最多接受幾張圖片（預設 4 張）、影片要開啟才接受（預設關閉：開啟會在啟動時多占記憶體），請求大小也有上限（預設 64 MB）。這些都在部署表單的 **Advanced** 區塊，預設值就能用。
- 帶圖片、音訊或影片的請求只留在你自己的部署上，絕不送往雲端供應商。
- 用量會計算媒體項目數；圖片的 token 包含在提示 token 裡。

## API 金鑰、限制與用量

- 程式以 **API 金鑰**（`fyk_…`）呼叫 `/v1`。每個人都在 **API keys** 建立自己的金鑰。金鑰只會顯示一次；伺服器只保留它的雜湊值。
- 金鑰可以限制只能用某些模型、可以設定到期日，也可以設定**限制**：每分鐘請求數和每分鐘 token 數。超過限制時，閘道會回應 429 並附上 `Retry-After`。
- 管理員可以設定**預設值**（給沒有自己限制的金鑰）和**上限**（任何人能為自己的金鑰設定的最大值），也可以為任何人的金鑰設定限制。管理員為別人的金鑰設定的限制會被**鎖定**：金鑰的擁有者無法更改。
- 每把金鑰也有**雲端**設定，並可以有每月**預算**（見下方）。
- **Usage** 依日期、模型、金鑰、使用者、來源以及本機或雲端，統計請求數、錯誤數、token 數和延遲。每個人都看得到自己的；管理員看得到所有人的。它的 **Cost** 分頁顯示雲端請求的費用（見下方）。

## 雲端供應商與分層

- **供應商**是 Forgeyard 以外的模型 API（OpenAI、Anthropic、Gemini、Azure OpenAI、OpenRouter，或你自己相容 OpenAI 的伺服器）。管理員連同金鑰一起新增；金鑰加密儲存，之後不會再顯示。
- `/v1` 上的每個模型名稱都是一條**路由**。路由有分成好幾**層**的**目標**：本機部署和供應商的模型。部署自己的路由一開始只有一層，就是這個部署。管理員可以加上雲端模型作為第二層，或建立只有雲端模型的路由。
- **本機優先。**只有在回答開始之前，而且本機這層無法使用、**忙碌**（每個副本都達到部署的 *Concurrent requests*）或回應 429 或 503 時，請求才會移到下一層。對本機 context 來說太長的提示，只有路由有設定時才會溢出。
- 每把 API 金鑰的**雲端**設定決定它的請求能不能離開你的網路：**Never**（預設值，1.2 以前的金鑰也都是）、**Only to spill**，或 **Allowed**（也包括只有雲端的模型）。勾選 **Local only** 的路由，以及帶著 `X-Forgeyard-Local-Only: 1` 的請求，也都不會離開。
- 回答會在 `X-Forgeyard-Target` 標明是誰提供的。Usage 會分開統計本機和雲端。

各供應商的細節請見[雲端供應商](cloud-providers.md)。

## 費用與預算

- **費用。** 每個請求在結束時計價一次。本機副本和你網路內的供應商費用是 0。雲端請求的費用是供應商回報的金額（OpenRouter 會回報），否則就是它的 token 數乘以供應商模型的**價格**（每百萬 token 的美元），價格由管理員輸入，或從 OpenRouter 的公開清單更新。模型沒有價格的雲端請求會算在 *without a price*，而不是算成 0。**Usage** → **Cost** 依日期、金鑰、個人、模型或供應商顯示費用。這是 Forgeyard 對供應商收費的估算，不是它們的帳單。
- **預算。** 預算是雲端請求每個日曆月（UTC）可以花的美元金額，可以設在 API 金鑰上（由擁有者設定，或由管理員設定並鎖定）、個人上（由管理員設定）或供應商上（由管理員設定）。請求送往雲端供應商之前，它最多可能花的費用會先對每個適用的預算**預留**；預算不夠時，請求就不會送往那個供應商。這時請求能留在本機就留在本機，只有在沒有其他目標能處理時，才會以 **402** 失敗。
- **警示。** 預算用到 80% 和 100% 時，Forgeyard 會在 **Audit log** 寫一筆事件，並在 **API keys**、**Usage** → **Cost** 和供應商的頁面顯示警告。

細節請見[費用與價格](cloud-providers.md#cost-and-prices)和[預算](cloud-providers.md#budgets)。

## 角色

| 角色 | 可以做的事 |
|---|---|
| `admin` | 所有事情：使用者、機器和它們的 GPU 存取權、模型目錄和 recipe、雲端供應商和路由、稽核紀錄、所有人的金鑰、限制和雲端設定 |
| `operator` | 執行工作負載和部署模型；以及 user 能做的所有事 |
| `user` | 瀏覽各頁面、在 Playground 和用自己的 API 金鑰使用已部署的模型、查看自己的用量 |

**擁有者**是第一個帳號。它永遠是管理員，不能被降級、停用或刪除，所以沒有人能把管理權限鎖死。新加入的人會收到一個一次性連結，用來設定自己的密碼；除非設定 `REGISTRATION=approval`，否則不開放自行註冊。

## 登入與工作階段

- 密碼至少 12 個字元，常見的密碼會被拒絕。連續登入失敗時，之後每次嘗試都要等待（`LOGIN_FREE_FAILURES`、`LOGIN_IP_FAILURES`）。
- 工作階段在 2 小時沒有任何請求後結束，最長 7 天（`SESSION_IDLE_MINUTES`、`SESSION_MAX_DAYS`）。
- 在 **My account**，你可以變更密碼（你的其他工作階段會被登出），並看到每個以你的身分登入的瀏覽器，每一個都可以登出。管理員可以在 **Users** 讓某人在所有地方登出、停用他，或給他一個新的設定密碼連結。
- **Audit log**（管理員）記錄登入、登入失敗，以及帳號、機器、模型、金鑰和供應商的變更，還有預算警示。
