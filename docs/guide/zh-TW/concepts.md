# 概念

Forgeyard 的各個部分怎麼搭在一起，依照你會碰到的順序說明。每一節都會講這是什麼、它幫你做什麼，以及要注意的地方。

## 機器與 agent

**機器**是 Forgeyard 可以在上面執行工作的任何電腦：GPU 伺服器、工作站，或只有 CPU 的電腦。每台機器都執行一個 **agent**（代理程式），這是一支小程式，它會：

- 回報機器的硬體：每張 GPU（型號、記憶體、驅動程式、負載、溫度）、CPU 和 RAM；
- 和伺服器保持一條連線，而這條連線是**由 agent 發起**的：伺服器永遠不需要主動連到機器，所以就算機器在防火牆或 NAT 後面，只要它連得到伺服器就能運作；
- 啟動、監看並停止伺服器要求它在這台機器上執行的東西。

機器只需要**加入**一次，使用從 **Machines** → **Add a machine** 取得的**加入權杖**（join token）：它只能用一次、15 分鐘內有效，伺服器只保留它的雜湊值。agent 會用它換到這台機器自己的**憑據**，存放在 agent 的狀態目錄（`/var/lib/forgeyard-agent`，權限 0600）。之後啟動就不再需要權杖。

agent 只透過伺服器的**憑證授權單位**（CA）來信任伺服器，並以加入指令裡的指紋釘選這個 CA：中間如果有別的機器拿著其他憑證，會被拒絕。請看[信任 CA](quick-start.md#2-create-the-owner-and-trust-the-ca)。

agent 連線中時，機器顯示 **online**；超過 30 秒沒有收到任何訊息時，顯示 **offline**（agent 每 10 秒送一次心跳）。agent 會自己重新連線。管理員可以**撤銷**一台機器（它的憑據立刻失效），或把它**移除**。

停止或重新啟動 agent **不會停掉它的模型和應用程式**：重新啟動的 agent 會找到它們並接手管理。這就是安裝的服務使用 `KillMode=process` 的原因。

agent 從 `/etc/forgeyard/agent.toml`、`FORGEYARD_*` 環境變數和命令列旗標讀取設定（[完整列表](reference.md#agent-settings)）。

**Machines** 頁面每台機器一張卡片，並用圖示標出它的種類：**NVIDIA GPU**、**AMD GPU**、**AMD APU**（和系統共用記憶體的 AMD GPU，例如 Radeon 8060S）或 **CPU only**。它的每張顯示卡是一排由下往上填的格子：先是 Forgeyard 保留的量，再來是其他用量（顯示卡上的其他程式，以及沒有宣告記憶體的 Forgeyard 應用程式），最後是可用的量。卡片也會顯示可用記憶體、在上面執行的部署和應用程式數量，以及它們的名稱。卡片上方的摘要計算每種機器各有幾台，以及離線的有幾台：*1 NVIDIA machine*、*2 CPU-only machines*（算的是機器，不管它有幾張卡）。點進一台機器就是它自己的頁面：**記憶體配置圖**（memory map）把每張卡依佔用者分段，標出名稱和保留量；另外還有在這台機器上執行的東西、GPU 存取權與 runtime，以及 agent 的資訊。管理員也在這裡撤銷或移除機器。

## GPU 存取權

預設情況下，Forgeyard 可以使用機器上的每一張 GPU。如果機器要和其他人或其他程式共用，管理員可以在機器的頁面（**Machines** → 該機器）→ **Change GPU access** 選擇 Forgeyard 可以用哪些卡。不在清單上的卡，絕不會分配給 Forgeyard 執行的任何東西。

- 分配給獨占副本的 GPU 只屬於那個副本。
- 共用一張卡的副本（嵌入模型、重排序模型、語音轉文字預設都是）只能使用自己保留的記憶體量，所以一張卡可以放好幾個。
- 記憶體以卡片當下回報的**可用**量為準，所以別人正在用的記憶體會被扣除，另外再保留一段安全餘裕（512 MiB）。
- 行程只會在 `CUDA_VISIBLE_DEVICES`（NVIDIA）或 `ROCR_VISIBLE_DEVICES`（AMD）裡拿到自己那幾張卡的 ID；容器也只會被傳入自己的卡。正在使用中的卡不能從清單中移除。

## GPU 共用

每個 GPU 部署不是 **Exclusive** 就是 **Share VRAM**：

- **Exclusive** 是對話 recipe 的預設：每個副本拿到整張卡，Forgeyard 不會在上面放其他東西。模型可以用到整張卡的算力。
- **Share VRAM** 是嵌入、重排序和語音轉文字的預設：副本只保留估算的記憶體量，其他共用的副本可以放進卡上其餘的空間（vLLM 也會被告知只用那麼多）。同一張卡上的副本共用算力，所以負載高時每個都會回應得慢一些。

獨占的副本和共用的副本絕不會用同一張卡：兩邊都必須共用。Forgeyard 會在共用有幫助時提醒：

- 獨占的模型只需要它那張卡一半以下的記憶體時，部署和修改頁面會說明（*This model needs 14.38 GiB of an 80.00 GiB card; with Share VRAM the rest can hold other models*）；
- 記憶體其實夠、只是被獨占擋住時，拒絕訊息會寫 *fits if both share VRAM*，並說出佔著那張卡的副本；
- **Setup health** 會為保留不到 24 GiB 以上卡片一半記憶體、正在執行的獨占副本提供一則說明（`deployment-could-share`）。

要在部署上修改，用 **Edit**：[修改部署](how-to.md#change-a-deployment)。

## 應用程式（已淘汰）

1.4 之前，主控台也能執行**應用程式（app）**：你自己的程式（容器或行程、服務或一次性任務），跑在你的機器上，也可以公開在 `/x/<name>` 讓 API 金鑰呼叫。Forgeyard 的重點是執行和管理模型，所以 1.4 起應用程式離開主控台，**1.5 會移除**它們：API 裡屬於應用程式的部分（`/api/workloads`）、範本，以及閘道的 `/x/`。在那之前，它們只能透過 API 使用，並會明白告知：每個回應都帶 `Deprecation` 標頭，伺服器紀錄會警告（每小時最多一次），只要還有任何應用程式，**Setup health** 就會警告。細節在[參考資料](reference.md#apps-deprecated)。

- 要提供模型，請在 **Serving** 部署它。物件偵測、影像分割和深度估計從 1.4 起是[視覺模型](#vision-models)。
- 內建引擎跑不了的模型，可以加一個**自訂引擎**（**Models → Engines → Add a custom engine**）：和內建的一樣是一份 recipe，指向它的容器映像檔或程式。

**Machines** 仍會列出佔用顯示卡的應用程式名稱，所以使用中的卡不會被顯示成空閒。模型部署也以 workload（runtime 為 `model`）執行：模型就是這樣跑的，這部分沒有淘汰。

## 模型、引擎與估算

模型放在兩個頁面。**Serving** 是現在正在執行的：依種類（chat、多模態 chat、嵌入、重排序、語音轉文字、文字轉語音、圖片、影片、視覺）把部署分組，每組標出它在 `/v1` 底下回應的路徑，每個部署一行：在哪裡執行（機器和顯示卡）、記憶體和狀態。**Deploy a model** 也在這裡，每個部署的頁面在 `/serving/<id>`。有[雲端備援](#cloud-providers-and-tiers)的部署會標出它的供應商，例如 *→ Gemini*；備援本身在部署的頁面上。

**Models** 是模型庫，也就是可以部署的東西，分成三個分頁：**Catalog**（目錄，預設）、**Engines**（引擎），以及管理員才有的 **Sources**（來源）。雲端模型和供應商在 **Cloud** 頁面（管理員）。1.3 的連結（`/models/deployments/<id>`、`/models/deploy`、`/models?tab=routes`、`/models/routes/<id>`、`/providers`）會打開新的位置。

- **目錄**列出你可以部署的模型。管理員可以從**推薦**清單、**Hugging Face 搜尋**，或從某個來源加入模型：`hf://org/name`、一個 GGUF 網址，或用 `local://` 指向機器上的某個目錄。加入模型時只會讀取它的資訊，不會下載。每一列都有 **Deploy** 和 **Download to…**。
- **引擎**（engine）描述某一類模型要怎麼執行：用哪個程式、哪個容器映像檔（以 digest 釘選）或發行版本、哪些參數，以及需要多少記憶體。API 和 YAML 檔案稱它為 **recipe**（配方；`/api/recipes`、`forgeyard/recipes/*.yaml`）；管理員在 **Engines** 分頁加入自訂的。內建的有：`vllm`（NVIDIA 和 AMD 上的對話模型）、`vllm-pooling`（嵌入與重排序）、`llama-cpp`（NVIDIA、AMD（ROCm 或 Vulkan）或 CPU 上的 GGUF）和 `faster-whisper`（語音轉文字）。
- **Sources**（管理員）說明模型可以從哪裡來：GGUF 網址允許的主機、`local://` 模型的目錄，以及伺服器的 Hugging Face 權杖。
- **估算**是一份副本需要的記憶體：權重、依你選的上下文長度和並行數計算的 KV cache、引擎本身的額外開銷、CUDA context，以及能讀圖片的模型的視覺編碼器。部署頁面會在下載任何東西之前，逐項顯示估算結果和放得下的位置。
- 每台機器上的**模型快取**（以 root 執行的 agent 預設是 `/srv/forgeyard-models`）保存下載下來的檔案，檔案會以 checksum 檢查，並由這台機器上的所有副本共用。容器會以唯讀方式掛載自己的模型。機器的頁面會列出快取裡有什麼和大小，並可刪除那台機器上沒有部署在用的項目（[釋出機器上的磁碟空間](how-to.md#free-disk-space-on-a-machine)）。**Download to…** 可以在部署之前先把模型和引擎放進去（[部署之前先下載模型](how-to.md#download-a-model-before-deploying-it)）。連不到 Hugging Face 或 GitHub 的機器會**經由伺服器**取得檔案，伺服器只轉送、不存檔；agent 會像檢查任何下載一樣檢查它們。有釘選的引擎映像檔也會這樣一層一層送過去，管理員也可以從機器的頁面上傳任何映像檔。模型在不在某台機器上，一律以它的 agent 回報的為準，所以手動複製過去的模型也算。
- **受限（gated）**的 Hugging Face 模型需要一個接受過它授權條款的帳號的權杖。伺服器保存**一個 Hugging Face 權杖**（管理員在 **Models → Sources** 設定，加密儲存），用來檢查和下載這些模型；部署也可以帶自己的權杖，對該部署優先使用。

## 部署與閘道

**部署**用一個引擎（recipe）執行一個模型，包含一個或多個副本。它的副本以 runtime 為 `model` 的 workload 執行，只在部署的頁面上看得到（不在 **Apps**）。Forgeyard 會：

1. 把每個副本放到放得下的地方。在放得下的機器之間，依序比較：
   - 過去一小時內**連不到**這個副本在那裡要下載的來源（模型的主機，例如 huggingface.co；引擎壓縮檔的主機，例如 github.com；或映像檔的 registry，例如 ghcr.io）的機器排在最後：只有其他機器都放不下時才會用它。名稱解析失敗、連線被拒或逾時、網路無法連線，才算「連不到」；HTTP 錯誤、權杖被拒或磁碟已滿則不算。agent 能**經由伺服器**下載的機器（1.4；它的 **Internet access for downloads** 是 **Auto** 或 **Always through the server**）會改用這個方式取得模型、引擎壓縮檔和有釘選的引擎映像檔，所以不會因此被避開（[經由伺服器把模型送到離線機器](how-to.md#give-an-offline-machine-models-through-the-server)）；
   - 盡可能把同一個部署的副本放在**不同機器**上；
   - 已經**快取了這個模型**的機器優先，其次是也已經有引擎的機器（process 引擎執行的壓縮檔，或容器引擎執行的映像檔）；
   - 然後是夠大的卡中最剛好的那張（讓整張空著的卡留給大模型）；
2. 副本在原本的機器上下載時**連不到來源**（在那裡停在 backoff）時，把它重新放到另一台放得下的機器上：這台機器會被記住一小時，視為連不到那個主機。指定了機器的部署會留在那台機器上繼續重試。副本會在部署的頁面上說明原因：*cpu-01 could not reach huggingface.co; placed on cpu-02 instead*；
3. 如果哪裡都放不下，就拒絕這個部署，並逐台機器說明原因和差多少；
4. 在那台機器上下載模型（如果引擎的映像檔還不在，也會拉取它）、啟動引擎，並等到它變成健康狀態。部署的頁面會顯示下載和拉取的進度；刪除部署會立刻停止這兩者。

每個就緒的部署都以它的模型名稱，在 **`https://<server>:7860/v1`**（也就是**閘道**）以 OpenAI API 提供服務：`/v1/models`、`/v1/chat/completions`、`/v1/completions`、`/v1/embeddings`、`/v1/rerank`、`/v1/score`、`/v1/audio/transcriptions` 和 `/translations`。`/v1/models` 列出你的金鑰可以用的模型；部署停止後，它會從清單消失，直到再次啟動為止，除非它的路由能把請求送到你的金鑰可以用的雲端供應商。

閘道會把每個請求送到正在處理中請求數最少的就緒副本；如果某個副本沒有回應，就改送下一個。副本無法繞過閘道直接使用：每個副本都有一把只有閘道知道的內部金鑰，agent 會拒絕送到副本連接埠的其他所有請求。

**Playground** 讓你以自己的身分、不需要 API 金鑰，透過同一個閘道試用模型。一個 **Model** 選單列出已就緒的模型，像 **Serving** 一樣依種類分組，用同樣的名稱和圖示（Chat、Multimodal chat、Embeddings、Rerank、Speech to text、Text to speech、Images、Video、Vision）；選一個就會開出它的面板：對話（串流，能讀圖片的模型也可以附上圖片）、嵌入、重排序、語音轉文字、**Speak**、**Image**、**Video**，或視覺面板（送一張圖片，得到方框、遮罩或深度圖）。網址會記住選的模型（`/playground?model=<name>`）；1.3 的 Vision 分頁網址（`/playground?tab=vision`）會開出第一個就緒的視覺模型，沒有時就打開選單。沒有任何就緒的模型時，頁面會這樣說明，並指向 **Models → Catalog** 去部署一個。它的請求在 Usage 裡算作 `console`；它的雲端設定對管理員是 **Allowed**，對其他人則是他們能替自己金鑰設定的最大值。

## 對話中的圖片、音訊與影片

能讀圖片的模型（Qwen3-VL、Gemma 3 與 4 等）在 `/v1/chat/completions` 以 OpenAI 的內容區塊（content parts）接收圖片。模型能接受什麼，是在加入目錄時讀出來的：從它的 `config.json`，或 GGUF 模型的 **projector 檔**（`mmproj-*.gguf`，llama.cpp 要靠它才看得到圖片）。目錄會把它和授權一起列出。

- 圖片可以用 `data:` URI 送，也可以用 `https://` 網址：**閘道會自己下載**，再把資料轉給引擎。引擎從不自己下載任何東西，而且閘道只連公開位址，所以請求沒辦法讓你的伺服器去存取你自己的內部網路。
- 每個部署一次請求最多接受幾張圖片（預設 4 張）、影片要開啟才接受（預設關閉：開啟會在啟動時多占記憶體），請求大小也有上限（預設 64 MB）。這些都在部署表單的 **Advanced** 區塊，預設值就能用。
- 帶圖片、音訊或影片的請求只留在你自己的部署上，絕不送往雲端供應商。
- 用量會計算媒體項目數；圖片的 token 包含在提示 token 裡。

## 文字轉語音

語音模型以 `/v1/audio/speech`（OpenAI 的文字轉語音呼叫）回應音訊本身。三種引擎提供這項服務：

| 引擎（配方） | 在哪裡跑 | 模型 | 語言 |
|---|---|---|---|
| vLLM-Omni（`vllm-omni-tts`） | NVIDIA GPU | Qwen3-TTS CustomVoice：九種內建聲音，可下風格指示 | 中文（含各地方言）、英文和另外八種語言 |
| llama.cpp（`llama-cpp`） | AMD GPU 與 APU（Vulkan 或 ROCm）、NVIDIA、CPU | 附 projector 的 TTS GGUF：Qwen3-TTS、Chatterbox | Qwen3-TTS：中文、英文等；Chatterbox：英文 |
| speaches（`speaches-tts`） | CPU、NVIDIA | Kokoro-82M（51 種聲音）、Piper 聲音 | 英文（及其他拉丁字母語言） |

- 語音模型有自己的**聲音**（Playground 會列出來）。像 `alloy` 這類 OpenAI 聲音名稱會換成模型的預設聲音，回應會標明換成哪一個。
- **不提供聲音複製**：不接受參考錄音，也不能上傳聲音，只有模型原本就有的聲音能說話。
- 每個部署一次請求最多接受多少字元（*Longest input*，在 **Advanced** 裡）。預設值剛好是引擎一次說得完的量。
- 用量會計算說出的**字元數**與**音訊長度**。金鑰的每分鐘 token 數中，一個字元算一個 token。
- 語音只留在你自己的部署上，絕不送往雲端供應商。

## 圖片生成

圖片模型以 `/v1/images/generations`（OpenAI 的圖片呼叫）回應，圖片以 base64 傳回。兩種引擎提供這項服務：

| 引擎（配方） | 在哪裡跑 | 模型 |
|---|---|---|
| vLLM-Omni（`vllm-omni-image`） | NVIDIA GPU | diffusers pipeline（帶 `model_index.json` 的儲存庫）：Z-Image-Turbo、Stable Diffusion XL、FLUX.1-schnell、Qwen-Image |
| stable-diffusion.cpp（`sd-cpp`） | AMD GPU 與 APU（Vulkan）、NVIDIA（CUDA）、CPU（行程，不需要 Docker） | GGUF 或單一檔案：Stable Diffusion 1.5 / XL checkpoint，以及在同一個儲存庫裡、旁邊附有文字編碼器與 VAE 的 Z-Image 和 FLUX |

- **只有 base64。** Forgeyard 不保留它產生的圖片，所以給不出網址：`response_format: url` 會被拒絕。請解碼 `data[].b64_json`。
- **每個部署都有上限，各有能用的預設值：**一次請求最多幾張圖片（4）、最長邊（模型自己的：Stable Diffusion 1.5 為 512，其他為 1024）、最多幾步（50）。記憶體估算依這些上限計算，所以調高上限，估算也會跟著變大。
- **一次一個，其餘排隊。** 一張圖片在 GPU 上要幾秒，在 CPU 上要幾分鐘。一個副本一次只處理一個請求（*Requests at once*）；其他請求依序在閘道裡等待。佇列滿了，請求會得到 429 並附上 `Retry-After`。
- **授權。** 目錄會顯示每個模型的授權，以及它是否 gated。推薦清單只收 Apache-2.0 與 OpenRAIL 的模型；FLUX.1-dev、SD-Turbo 與 SD3.5 不在清單上（條款禁止商業使用或限制營收），但可以自己手動加入。OpenRAIL 授權的模型（SDXL、SD 1.5）可以商業使用，但授權禁止某些用途：它們的卡片會標出授權並附上連結，Gemma 與 Llama 也一樣。
- **不過濾提示。** Forgeyard 只檢查請求的格式與上限，不檢查它要求畫什麼。
- 用量會計算**圖片數**、它們的**千像素數**和**忙碌時間**（在 GPU 上即 GPU 時間）。
- 圖片只留在你自己的部署上，絕不送往雲端供應商。

## 影片生成

影片模型以 `/v1/videos`（OpenAI 的 Videos API）回應。一段影片要好幾分鐘，所以它是一個**工作（job）**：請求會立刻回應這個工作（`queued`），你輪詢它直到 `completed`（或 `failed`），再取回 MP4。由一種引擎提供：NVIDIA GPU 上的 vLLM-Omni（配方 `vllm-omni-video`），搭配 Wan 文字轉影片 pipeline（Wan2.1-T2V-1.3B、Wan2.2-TI2V-5B）。

- **工作只在一個副本上。** 閘道把它送到工作最少的就緒副本，之後只向那個副本詢問它的狀態和檔案。引擎把工作放在記憶體裡、檔案放在自己的磁碟上。
- **副本不在了，它的工作也跟著不在。** 副本被停止、搬移或刪除，或它的引擎重新啟動時，它的工作會回報 `failed` 並說明原因（`replica_gone`、`replica_restarted`、`video_lost`）：請重新要求。已完成的影片，若副本已不在，取內容時回應 410。
- **伺服器重新啟動時工作還在。** 它們存在伺服器的資料庫裡，副本也繼續工作；伺服器會重新接手。
- **結果會過期。** 完成的影片在部署的 *Keep results*（1,440 分鐘，一天）內可以取回；之後會在副本上刪除，取內容時回應 410。引擎自己也會在那之後一小時清掉舊檔，以防有刪除漏掉。
- **每個部署都有上限，各有能用的預設值：**最長的影片（5 秒）、最大的尺寸（模型自己的：Wan2.1 為 832x480，Wan2.2 為 1280x704）、等待中或製作中的工作數（8），其中單一金鑰的工作數（2），以及一個工作最多能花多久（一小時）。記憶體估算依最長、最大的影片計算。
- 1.3 **只支援文字轉影片**：圖片轉影片的參考輸入會被拒絕。
- **不保留提示**，而且一把金鑰只看得到自己的工作。
- 用量計算**每段影片一個請求**、它的**長度**和**忙碌時間**（GPU 時間）。
- 影片只留在你自己的部署上，絕不送往雲端供應商。

## 視覺模型

視覺模型（1.4）看一張圖片：**物件偵測**（方框、標籤和分數：RT-DETR、D-FINE、DETR…）、**影像分割**（一個點或一個方框所指東西的遮罩：SAM 2 和 2.1）和**深度估計**（每個像素有多近：Depth Anything、DPT…）。它們和其他模型一樣是模型種類：從 Hugging Face 加入目錄（推薦了三個）、部署後列在 **Serving → Vision**、在 **Playground** 試用（模型選單的 *Vision* 底下）、用 API 金鑰呼叫。

- **只有一種引擎，Forgeyard 自己的。** `vision` 配方在與伺服器同版本的 `forgeyard-vision` 映像檔裡執行 Forgeyard 的視覺伺服器（PyTorch 上的 transformers）：NVIDIA GPU 上用 CUDA 版，以記憶體共用一張卡；任何機器都能用 CPU 版（AMD 機器用它的 CPU 執行：還沒有 ROCm 版）。模型和其他模型一樣來自機器的模型快取。
- **哪些模型：**目錄讀模型的 `config.json`。`…ForObjectDetection` 架構是偵測，SAM 2 是分割，`…ForDepthEstimation` 是深度；其他都不是視覺模型。**只接受寬鬆授權**（Apache-2.0、MIT、BSD）：Depth Anything V2 Base 和 Large（CC-BY-NC-4.0）以及 Ultralytics 的 YOLO 權重（AGPL-3.0）不能加入。
- **自己的 API：**`/v1/vision/detect`、`/v1/vision/segment` 和 `/v1/vision/depth`，每個請求一張圖片（multipart，或 JSON 裡的 base64），回應是 JSON；遮罩和深度圖是 base64 的 PNG。OpenAI SDK 沒有這個 API：任何 HTTP 用戶端都能呼叫。
- 每個副本**一次處理一張圖片**；其餘排隊等候。要更高吞吐量就多開副本。
- 用量計**每個請求一張圖片**、它的千像素數和忙碌時間。圖片只留在你自己的部署上：絕不送往雲端供應商，也不會被保存。

## API 金鑰、限制與用量

- 程式以 **API 金鑰**（`fyk_…`）呼叫 `/v1`。每個人都在 **API keys** 建立自己的金鑰。金鑰只會顯示一次；伺服器只保留它的雜湊值。
- **API keys** 的清單只列出還能用的金鑰。已撤銷和已過期的金鑰收在清單下方的一列 **Show N revoked keys** 裡，*Mine* 和 *Everyone's* 都一樣；**Usage** 和 **Audit log** 仍然會列出它們。*Limits* 欄只顯示金鑰有設定的限制（「3 requests/min」、「10k tokens/min」），沒有就是 *No limits*。
- 金鑰可以限制只能用某些模型、可以設定到期日，也可以設定**限制**：每分鐘請求數和每分鐘 token 數。超過限制時，閘道會回應 429 並附上 `Retry-After`。
- 管理員可以設定**預設值**（給沒有自己限制的金鑰）和**上限**（任何人能為自己的金鑰設定的最大值），也可以為任何人的金鑰設定限制。管理員為別人的金鑰設定的限制會被**鎖定**：金鑰的擁有者無法更改。
- 每把金鑰也有**雲端**設定，並可以有每月**預算**（見下方）。
- **Usage** 依日期、模型、金鑰、使用者、來源以及本機或雲端，統計請求數、錯誤數、token 數和延遲。每個人都看得到自己的；管理員看得到所有人的。它的 **Cost** 分頁顯示雲端請求的費用（見下方）。
- 圖表下方的表格依排序的欄位列出前 15 列（預設是請求數；**Cost** 分頁是費用；依日期分組時最新的日子在前）。其餘的加總成最後一列 *N others*，所以表格的加總仍和總數一致；**Show all N** 會列出每一列。點欄位標題就依該欄排序，再點一次則反過來排。在手機上每列只佔一行：名稱和排序所依的數字；點一下就展開其他欄位，順序用 **Sort by** 選。太長的名稱會被截斷：把游標移上去，或展開該列，就能看到完整名稱。
- 兩個分頁上的 **Over time** 會把其中一項數字畫成折線圖：按日（最近 30 天）、按週（13 週，從週一算起）或按月（12 個月），可以只看總數，或依金鑰、模型、供應商或個人（管理員選 **Everyone** 時）各畫一條線。最大的五條各自成線，其餘加總為 *Other*。把游標移到點上或用方向鍵可以讀出該期間的數值；**Show the numbers** 會以表格列出。日期以 UTC 計，最新的一期還在進行中（虛線）。

## 雲端供應商與分層

- **供應商**是 Forgeyard 以外的模型 API（OpenAI、Anthropic、Gemini、Azure OpenAI、OpenRouter，或你自己相容 OpenAI 的伺服器）。管理員連同金鑰一起新增；金鑰加密儲存，之後不會再顯示。
- `/v1` 上的每個模型名稱（在 API 裡）都是一條**路由**。路由有分成好幾**層**的**目標**：本機部署和供應商的模型。部署自己的路由一開始只有一層，就是這個部署。管理員可以在後面加上雲端模型，也就是部署的**雲端備援**，在它的頁面上設定。管理員也可以建立**雲端模型**：替供應商的模型取一個自己的名稱，在 **Cloud → Cloud models**。
- **本機優先。**只有在回答開始之前，而且本機這層無法使用、**忙碌**（每個副本都達到部署的 *Concurrent requests*）或回應 429 或 503 時，請求才會移到下一層。對本機 context 來說太長的提示，只有路由有設定時才會溢出。
- 每把 API 金鑰的**雲端**設定決定它的請求能不能離開你的網路：**Never**（預設值，1.2 以前的金鑰也都是）、**Only to spill**，或 **Allowed**（也包括只有雲端的模型）。勾選 **Local only** 的路由，以及帶著 `X-Forgeyard-Local-Only: 1` 的請求，也都不會離開。
- **雲端政策**（管理員在 **API keys** 的選擇）是把兩個值合成一個：新金鑰拿到什麼，以及大家最多能給自己的金鑰什麼。*No cloud*、*People may opt in to spill*、*Spill by default* 和 *Cloud allowed* 是常用的組合；*Custom* 會顯示兩個值。
- 供應商不是在**你的網路外**（要花錢，只有允許使用雲端的金鑰能用），就是在**網路內**（每把金鑰都能用，不套用預算）。新的供應商會依它的種類和位址預先勾好，由管理員確認。
- 回答會在 `X-Forgeyard-Target` 標明是誰提供的。Usage 會分開統計本機和雲端。

各供應商的細節請見[雲端供應商](cloud-providers.md)。

## 費用與預算

- **費用。** 每個請求在結束時計價一次。本機副本和你網路內的供應商費用是 0。雲端請求的費用是供應商回報的金額（OpenRouter 會回報），否則就是它的 token 數乘以供應商模型的**價格**（每百萬 token 的美元），價格由管理員輸入，或從 OpenRouter 的公開清單更新。模型沒有價格的雲端請求會算在 *without a price*，而不是算成 0。**Usage** → **Cost** 依日期、金鑰、個人、模型或供應商顯示費用。這是 Forgeyard 對供應商收費的估算，不是它們的帳單。
- **預算。** 預算是雲端請求每個日曆月（UTC）可以花的美元金額，可以設在 API 金鑰上（由擁有者設定，或由管理員設定並鎖定）、個人上（由管理員設定）或供應商上（由管理員設定）。請求送往雲端供應商之前，它最多可能花的費用會先對每個適用的預算**預留**；預算不夠時，請求就不會送往那個供應商。這時請求能留在本機就留在本機，只有在沒有其他目標能處理時，才會以 **402** 失敗。
- **警示。** 預算用到 80% 和 100% 時，Forgeyard 會在 **Audit log** 寫一筆事件，並在 **API keys**、**Usage** → **Cost** 和供應商的頁面顯示警告。

細節請見[費用與價格](cloud-providers.md#cost-and-prices)和[預算](cloud-providers.md#budgets)。

## 角色

| 角色 | 可以做的事 |
|---|---|
| `admin` | 所有事情：使用者、機器和它們的 GPU 存取權、模型目錄和引擎、雲端供應商和路由、稽核紀錄、所有人的金鑰、限制和雲端設定 |
| `operator` | 執行應用程式和部署模型；以及 user 能做的所有事 |
| `user` | 瀏覽各頁面、在 Playground 和用自己的 API 金鑰使用已部署的模型、查看自己的用量 |

**擁有者**是第一個帳號。它永遠是管理員，不能被降級、停用或刪除，所以沒有人能把管理權限鎖死。新加入的人會收到一個一次性連結，用來設定自己的密碼；除非設定 `REGISTRATION=approval`，否則不開放自行註冊。

## 登入與工作階段

- 密碼至少 12 個字元，常見的密碼會被拒絕。連續登入失敗時，之後每次嘗試都要等待（`LOGIN_FREE_FAILURES`、`LOGIN_IP_FAILURES`）。
- 工作階段在 2 小時沒有任何請求後結束，最長 7 天（`SESSION_IDLE_MINUTES`、`SESSION_MAX_DAYS`）。
- 在 **My account**，你可以變更密碼（你的其他工作階段會被登出），並看到每個以你的身分登入的瀏覽器，每一個都可以登出。管理員可以在 **Users** 讓某人在所有地方登出、停用他，或給他一個新的設定密碼連結。
- **Audit log**（管理員）記錄登入、登入失敗，以及帳號、機器、模型、金鑰和供應商的變更，還有預算警示。
